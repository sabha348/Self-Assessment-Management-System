# Evals

Two evals back the claims in the main README:

| Eval | Question it answers | Labels written by |
|---|---|---|
| **Retrieval** (`retrieval/`) | For a student's question, does the RAG service return a chunk from the page that answers it in the top 5? (recall@5, MRR) | the project owner, by hand |
| **Grader agreement** (`grading/`, M3) | Does the auto-grader agree with a human on free-text answers, and where does it disagree? | the project owner, by hand |

Labels are never generated by an LLM: an eval whose labels come from the
model family being evaluated would measure self-agreement, not quality.

## Retrieval eval

**Corpus.** *Think Python, 2nd edition* by Allen B. Downey (CC BY-NC 3.0),
244 pages. It is not committed; `corpus/fetch_corpus.sh` downloads it and
checks its SHA-256.

**Labels: page level, not chunk level.** Each question is labelled with the
page(s) that contain the answer. A retrieved chunk counts as relevant if its
page range overlaps a gold page. Because labels don't refer to chunk ids,
the same labels can compare chunk sizes, embedding models and retrieval
modes without relabelling.

**Writing labels** (`data/retrieval_labels.txt`, see the template):

```
45, 46 | What does the in operator do when used with a dictionary? | concept
12 | Why does 1/2 give 0.5 in Python 3? | paraphrase
```

Aim for 25–40 questions and vary them on purpose, so the results say
something:

- **paraphrase**: ask in your own words, not the book's ("make a loop stop
  early" rather than "break statement"). This is where dense retrieval
  should beat keyword search.
- **exact-term**: questions using a specific name (`isinstance`, `KeyError`).
  Keyword search should do well here.
- **concept**: "why" and "when would you" questions.
- **multi-page**: answers spread over two pages.
- Spread questions across the whole book, not just the first chapters.

**Running** (Postgres+pgvector up, `GOOGLE_API_KEY` set):

```bash
docker compose -f compose.dev.yml up -d db
evals/corpus/fetch_corpus.sh
pip install -r rag_service/requirements.txt
python evals/retrieval/run_retrieval_eval.py --labels evals/data/retrieval_labels.txt
# variants, same labels:
python evals/retrieval/run_retrieval_eval.py --chunk-size 800 --chunk-overlap 100
```

The first run embeds the book (about 4 minutes on Gemini's free tier, which
allows 100 embedded texts per minute); later runs reuse the stored vectors.
Each run writes `evals/runs/<timestamp>/` with `summary.md`, `summary.json`
and `per_question.csv` (top-5 pages and first-hit rank per mode), so every
miss can be inspected.

**Metrics.** `recall@k` is the share of questions with at least one relevant
chunk in the top k (hit rate); `MRR@5` is the mean of 1/rank of the first
relevant chunk (0 if none in the top 5).
